# 邮件发送：客户解析

在现有“邮件发送”页面增加“客户解析”页签，侧边栏与导航路由不变。

## 使用步骤

1. 在客户管理导入名单，补全国家、网站及业务资料；进入邮件发送 → 客户解析。
2. 选择至多20个客户／联系人，填写目标国家、推广产品及签名。可选读取公开官网；默认产品与签名可修改。
3. 解析结果按水处理、阀门、管道管件、工程项目、需求待确认匹配英文首封邮件。依据、来源、核对时间及未核实项与正文同时展示。
4. 逐封编辑并保存，勾选要发送的内容。生成与保存不触发发送；已联系、已回复、无效、退订、重复或国家不匹配的记录不能进入本次首次开发任务。
5. 填写明确的当地开始时间与IANA时区；页面显示对应北京时间。设置每轮数量、间隔与总轮数，检查容量后点击“创建并启用定时任务”。实际SMTP发件地址必须匹配签名邮箱。
6. 同一个任务保存各自确认的邮件正文，通过既有调度器分批执行。发信任务页继续承担暂停、取消和结果查看；不会自动发后续跟进。

解析使用规则与官网关键词，**不是调用生成式AI模型或完整企业尽调**。官网不可读时保留资料缺口并使用条件式询问，不虚构资质、交期、库存、采购意向等事实。未识别业务类型的邮件默认不勾选。首次开发限制基于CRM已记录状态，不能识别未同步到CRM的外部回复。

## 实现与数据

- API：`GET/POST /api/outreach-workflows`；`GET /:id`；`PUT /:id/drafts/:key`；`POST /:id/schedule`。
- 仅管理员／销售可用；销售沿用现有客户归属与任务归属限制。
- 草稿保存在 `email_tasks.outreach_data`，含来源、签名、逐客邮件及修订号。已确认的邮件快照不可经通用任务更新接口改写。
- 一次解析请求使用固定请求ID；重复确认同一任务返回既有排程；修订号防止旧页面覆盖新编辑。
- 确认排程时，在单个数据库事务中占用邮箱、创建收件人快照并激活任务。`outreach_reservations.email` 主键阻止多个客户解析任务并发占用同一邮箱；排程失败整批回滚。
- 取消任务仅释放尚未尝试发送的邮箱。已发送或结果不明的邮箱保留，避免盲目重发。
- 发送时使用确切收件人与正文快照，再检查当前客户阶段、营销状态、邮箱和发送历史；不回退到通用正文。既有退订、限速、当地工作窗口、失败记录机制继续生效。
- 官网读取只支持标准公开HTTP(S)地址，检查DNS并固定连接地址；拒绝内网、凭据、IP直连、跨站跳转，并限制超时与响应大小。读取失败不阻塞草稿生成，但展示未核验状态。

## 部署与验证

先运行已有迁移流程 `npm run db:migrate -w backend`，再启动新后端；迁移 `20261021_outreach_analysis` 为增量、可重复执行，不改写历史邮件任务。无需新增第三方依赖或模型密钥。

验证包括新增客户解析单元测试、HTTP权限／输入验证、前端编辑勾选与排程测试、UTC／目标时区及夏令时边界测试，以及真实MySQL重复确认、跨任务占用、失败回滚与取消释放检查。真实数据库测试仅使用临时测试库及假的SMTP设置，不进行发信。

旧版后端不了解逐客快照；如需降级，应先暂停新增客户解析任务并保留增量字段及占用表。既有普通邮件任务不依赖新功能。

本次改动不迁移、重建、取消或重新发送线上已经安排的20家任务。
